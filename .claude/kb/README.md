# Knowledge Base Index

Curated, agent-consumable cheatsheets & lessons. Maintained by
`@agent-knowledge-curator`. One topic per file; terse and command-first (see
`_template.md`). Raw, un-distilled sources are archived under `docs/course/`.

## How to add knowledge
Hand a source (repo file path, pasted text, or URL) to the curator:
> `@agent-knowledge-curator curate <source>`
It classifies, dedupes, writes the entry (with a `summary:` in the frontmatter),
and the index below is regenerated from that frontmatter — no manual list to keep
in sync.

## Cross-links & graph
Every entry carries a `- Relacionado: [[slug]], [[slug]]` line in its
`## References` section (2–5 genuinely related notes). These `[[wikilinks]]` are
the KB's connective tissue and what the graph renders. Add a `Relacionado` line
to every new note, and a back-link from its strongest neighbor — a note without
one shows up as an isolated island.

One script builds both the offline graph **and** the index table below:
```bash
python3 .claude/kb/_graph/build_graph.py     # regen graph + README index after editing notes
xdg-open .claude/kb/_graph/kb-graph.html
```

## Categories
- `tools/`       — one file per tool/toolset (flags, invocation, gotchas)
- `techniques/`  — one file per attack technique
- `payloads/`    — reusable payloads/snippets by theme
- `platforms/`   — per-target/per-product facts & process

> by `_graph/build_graph.py`. Do not edit it by hand — change a note's `summary:`
> (or add/remove a note) and re-run the script. To add an entry it must have
> frontmatter with `category`, `updated`, and `summary` (see `_template.md`).
