# 008 — TUI panel: critique of the current state and target design

> **Note (2026-11-11):** input document. Where it contradicts `spec.md` or `plan.md`, those prevail. Known differences: the theme follows Pi's (there is no `GEKKO_THEME`; the §4.5 table is the FALLBACK palette), and folding into the bar depends on the rail not being drawn, not only on width.

> Output of the `tui-design` skill. It is design, not product code. None of this is implemented.
> Confidence labels: **[V]** verified with a capture or a code read · **[I]** inferred · **[?]** unverified.

## 1. Target and intent

- **Surface:** the right-hand panel (`toolbox/gekko-sidebar.mjs`, fed by `panelDetailLines()` from
  `toolbox/gekko-panel.ts` via `writePanelState()` in `toolbox/gekko-guard.ts`) + the bottom status bar.
- **Intent:** *shape* — from a flat list inside a box to a column of collapsible cards with a light/dark
  theme, in the style of the gentle-shell rail.

### Findings

**P0**
- **F1 — At 80 columns the guard state disappears from the screen.** The 12-column sidebar (C80) cuts off at
  row 23 and never shows techniques, KB or the block; and while its `.alive` heartbeat is fresh the guard
  *hides* the horizontal widget (`sidebarLive()` → `widget = undefined`, `gekko-guard.ts:438`). Result: the
  only surface that meets AC14 is switched off and the one that remains does not meet it. **[V]** capture + code; **[I]** the
  combined effect in a live Pi (I did not run it).

**P1**
- **F2 — A dead guard looks alive.** `readLines()` does not check the file's age; if Pi dies, the panel keeps
  saying `guard ON` indefinitely. The costly error is the false "protected". **[V]** code (`gekko-sidebar.mjs:22–29`).
- **F3 — Wrapping breaks key/value reading.** Split IPs (`192.0.2.4` / `2,` C80 19–20), split words
  (`destructi` / `vo` C80 10–11), a technique taking two rows and losing its indentation (C180 16–17).
- **F4 — Width is the scarce resource and it is given away.** 16 % = 28 columns at 180, 22 at 140; the outer box and
  the margin consume 3 of them. There is spare height (C180 33–49) and too little width.
- **F5 — Nothing is ordered by importance.** The latest block —the most actionable item— is at the end (C180 29–32) and
  at 140 columns ends on row 38 of 40: one more host in scope pushes it off screen without notice.
- **F6 — No theme.** Fixed blue `#4FA3FF`: 7.2:1 on a dark background, **2.6:1 on white** (borders and title almost
  invisible on a light terminal). It is not the brand accent (the comment calls it "LIME").

**P2**
- **F7 —** Title `GEKKO  panel en vivo` + empty row: 2–4 rows with no state (C140 2–4).
- **F8 —** The legend `técnicas · ✓auto ?pregunta ✗no:` costs 2 permanent rows (C180 14–15).
- **F9 —** Noise inside a datum: `alt+k detalle (subag. no instrum.)` (C180 27–28).
- **F10 —** Shells as an inline list `nombre[estado], …`: does not scale or align (C180 11–13).
- **F11 —** No interaction: what is not of interest cannot be folded; the focused pane swallows keys with no feedback.

**P3**
- **F12 —** A `LIME` constant that holds blue; `scope` in English among Spanish labels.

## 4. Target design

### 4.1 Geometry

- **Rail:** `width = clamp(36, 25 % of the terminal, 48)` → 45 at 180 columns, 36 at 140. No outer box
  (the tmux pane border already separates). No title of its own.
- **Breakpoint 140:** below it, the rail is not drawn and its essentials move to the bar. Existing
  mechanism: without the `.alive` heartbeat the guard stops considering the sidebar alive **[V]**; what is missing is for the
  launcher/`window-resized` hook to close and reopen the pane when crossing the threshold **[?]**.
- **Card:** header = named rule (`▾ NAME ──── summary`), body with a thin left border `│`.
  The header is the separator: zero empty rows.
- **Bar:** one row, Pi's footer (it lives in Pi's pane: 134 columns at 180, 103 at 140, 80 at 80).

### 4.2 Cards

Order = priority; the top one is the last to give up space.

| # | Card | Right header | Body | Collapsed | Equivalent in gentle-shell |
|---|---|---|---|---|---|
| 1 | **GUARD** | `ON` / `✗ AUSENTE` / `✗ FALLÓ` | destructive · limits (loop-guard, calls) · last block | `ON · destructivo OFF · ✗ 1 bloqueo` | — (own) |
| 2 | **SCOPE** | `3 hosts` / `✗ vacío` | one host per row | `192.0.2.42 +2` | — (own) |
| 3 | **TÉCNICAS** | `2 auto · 7 preguntan` | one technique per row, glyph ✓ ? ✗ + target | `✓ bruteforce, binary-upload` | — (own) |
| 4 | **SHELLS** | `1 open · 1 stale` | glyph + state + name | `● rev-www  ◌ ssh-svc` | INTEGRATIONS |
| 5 | **HALLAZGOS** | `2/5 confirmados` | count per ledger state | `✓ 2  ? 2  ✗ 1` | TODOS n/m |
| 6 | **KB** | `7 leídos · 19 consultas` | last 3 files read, with age | `últ. techniques/…` | — (own) |
| 7 | **SESIÓN** | `▸ bash 12s` (activity) | tools ok/blocked/error · subagent | `41 tools · 2 bloq · 1 error` | STATS + AGENTS |
| 8 | **CAMBIOS** | `17 files +412 −38` | top 2 files + `… +N más` | same as the header | CHANGES |

Mapping decisions:
- **AGENTS is not a card:** at most one subagent, in the foreground → one row in SESIÓN.
- **INTEGRATIONS → SHELLS:** what is "connected" in a pentest is the operator's own verified shells.
- **TODOS → HALLAZGOS:** the measurable progress of an engagement is confirmed/total in the ledger.
- **One datum, one place:** mode, model, ctx % and turn live in the bar and are **not** repeated in cards. The
  branch lives in the bar; the dirty-file count lives in CAMBIOS (the bar only marks `*`).

### 4.5 Color roles

At most four typographic roles: title = bold, label = dim, value = normal, alert = color + glyph.

| Role | Use | Dark | Contrast (on `#0D1117` / `#1E1E1E` / `#000`) | Light | Contrast (on `#FFF` / `#F6F8FA` / `#FDF6E3`) |
|---|---|---|---|---|---|
| `fg` | values | terminal default | — | terminal default | — |
| `dim` | labels, header rule, age | `#8B949E` | 6.2 / 5.4 / 6.8 | `#59636E` | 6.1 / 5.7 / 5.7 |
| `border` | body `│` | `#484F58` | 2.3 / 2.0 / 2.5 (decorative) | `#8C959F` | 3.0 / 2.9 / 2.8 (decorative) |
| `accent` | `▾ ▸`, card name, mode badge, `▰` | `#C0F425` (brand lime) | 14.6 / 12.9 / 16.2 | `#3F6212` | 7.1 / 6.6 / 6.6 |
| `ok` | `✓`, `●` | = `accent` | — | = `accent` | — |
| `warn` | `?` always, `◌ stale`, empty scope, stale data | `#E3B341` | 9.7 / 8.6 / 10.8 | `#8A4B00` | 6.8 / 6.4 / 6.3 |
| `danger` | `✗`, guard AUSENTE/FALLÓ, block | `#FF7B72` | 7.5 / 6.6 / 8.3 | `#B42318` | 6.6 / 6.2 / 6.1 |

Rationale:
- **Light is designed, not inverted.** The lime `#C0F425` on white gives **1.3:1** (illegible); the light
  accent is the same family darkened (`#3F6212`, ≥6.6:1). All text in both themes exceeds 4.5:1 (AA) on
  the three backgrounds tested; `border` is decorative and carries no information.
- **No background is painted.** The rail uses the terminal background; the mode badge is `▌AGRESIVO▐` in bold
  `accent` (not reverse video, which fails with lime on light).
- **Without color (`NO_COLOR`, 16 colors, text capture):** what remains is bold/dim + glyph + word. Every state
  has a glyph and a word: `✓ auto`, `? pregunta`, `✗ bloqueo`, `● open`, `◌ stale`, `○ closed`. AC14 is met
  by construction and is assertable in the selftest (render with `theme = none`).
- **Theme selection:** explicit `GEKKO_THEME=dark|light|none` → otherwise the theme the guard publishes from
  Pi → otherwise dark. OSC 11 autodetection **[?]** is unverified under tmux; I do not take it as good.

```
│ ● open  rev-www                        │ border · ● ok · open dim · rev-www fg
│ ◌ stale ssh-svc                        │ border · ◌ warn · stale warn · ssh-svc fg
```

### 4.7 Interaction

Rule: a rail click or key only folds, unfolds or moves the cursor. It **never** changes mode, scope or
policy; the rail writes nothing the guard reads. The fold state belongs to the sidebar
(`.gekko-state/panel.ui.json`, UI only).

| Input | Where | Effect |
|---|---|---|
| Left click | a card's header row (its full width) | folds/unfolds that card |
| Click | any other row | nothing |
| `↑ ↓` / `k j` | focused rail | moves the card cursor (the header with the cursor is underlined; the `▾/▸` glyph does not change) |
| `enter` / `espacio` | focused rail | folds/unfolds the cursor's card |
| `1`–`8` | focused rail | folds/unfolds card N |
| `a` / `z` | focused rail | expand all / collapse all |
| `esc` | focused rail | returns focus to Pi's pane |
| `Ctrl+C` | focused rail | closes the rail (as today) |
| other keys | focused rail | swallowed (as today) |

- **Hit map** of the pure renderer: `[{ row, card, action: "toggle" }]`, header rows only. It is
  what the selftest asserts ("no hit carries an action other than toggle").
- **Focus risk [?]:** with `mouse on`, tmux's default binding selects the pane on click →
  the operator folds a card and their next key lands in the rail, which swallows it. Proposed mitigation:
  after processing a click the sidebar returns focus (`tmux last-pane`), or the launcher redefines
  `MouseDown1Pane` so as not to select panes marked `@gekko_sidebar`. Neither has been tested.
- **Side effect [I]:** when requesting mouse reporting (SGR 1006) the pane stops allowing text selection
  by simple drag (it remains with Shift). Dragging the pane border remains tmux's.
- **Discoverability:** the `▾/▸` glyph on each header is the hint; no permanent help row.

### 4.8 States

| State | Behavior |
|---|---|
| **Pi has not started yet** (no file) | one row: `esperando pi…` (dim). No empty cards. |
| **Stale data** (the JSON carries `ts`; the guard rewrites it on a timer; age > 10 s) | first row `⚠ sin datos hace 14s` (warn); the last frame is kept in dim; GUARD's header becomes `? desconocido`. `ON` is never shown again. Closes F2. |
| **Unreadable JSON / unknown version** | the last good frame is kept + `⚠ estado ilegible`. Unparsed content is not painted. |
| **Guard AUSENTE / FALLÓ** | GUARD: header `✗ FALLÓ` (danger), row `AGRESIVO deshabilitado`; **cannot be collapsed** and goes to the bar. |
| **Empty scope** | header `✗ vacío`, row `fail-closed: nada autorizado` (warn). |
| **No shells / no block / KB with no reads / clean tree** | the card stays as a single header row with `0` / `—` / `limpio`; no body. |
| **No ledger wired** | HALLAZGOS is not drawn (a field with no source = out, not a false `0/0`). |
| **Long text** | values truncate with `…` at the end; paths truncate on the left (`…/active-directory.md`); IPs/hosts are not truncated before words. The full block reason lives in Pi's overlay. |
| **1000 items** (scope, shells, KB) | body capped per card (scope 6, shells 6, KB 3, changes 3: its three fixed rows) + a `… +994 más` row; the header carries the real total. Render O(cap), not O(n). |
| **Does not fit the height** | cards collapse by themselves from the bottom (8→1) until it fits; an auto-collapsed card is marked `▸` all the same and the operator can reopen it (then the next one yields). GUARD never yields. No scroll in v1. |
| **Hostile content** | every string goes through `redactSummary()`/`stripControl()` before entering the JSON, as today; the sidebar does not interpret escapes in the data. |

## 5. Implementation contract (for the plan, not code)

- The guard publishes `panel.json` (atomic, as today): `{ v, ts, theme, cards: [{ id, title, right, summary, rows: [{ glyph, role, label, value }] , pinned }], bar: {…} }`.
- `renderRail(state, width, height, theme, ui) → { lines, hits }` pure, in `gekko-panel.ts`; the sidebar only
  reads, calls, paints and translates clicks with `hits`.
- Assertable criteria in the selftest: no line exceeds `width`; with `theme = none` there is no color SGR and
  every state keeps glyph+word; `hits` only contains `toggle`; at 1000 hosts the frame does not exceed `height`;
  a stale state never renders `ON`; at `width < 140` there is no rail and the bar contains mode, guard, scope and block.
